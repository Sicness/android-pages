# CLAUDE.md

## Что это

Страница «Наши приложения» — `https://android.darklogic.ru/`. На ней список наших
Android-приложений. Каждое приложение ведёт на неё из своего меню, чтобы его
пользователи узнавали об остальных.

Список живёт на странице, а не в коде приложений: новое приложение появляется у
всех пользователей сразу, без релизов.

У этого файла два читателя:

- тот, кто добавляет пункт меню в **своё приложение**, — раздел «Подключить приложение»;
- тот, кто меняет **саму страницу**, — разделы после него.

## Подключить приложение

Приложение показывает пункт меню и по нажатию открывает страницу во внешнем
браузере, передав в ссылке, кто оно, язык и стор. Всё остальное делает страница.

Образец — МДС: `../MDS/app/src/main/java/ru/darklogic/mds/tools/AppsPage.java`
(ссылка, стор, отметка «новое», событие) и `Drawer.java` там же (пункт и точки).

### Ссылка

```
https://android.darklogic.ru/?utm_source=<id>&lang=<ru|en>&store=<gp|rustore>
```

| Параметр | Значение | Что делает страница |
|---|---|---|
| `utm_source` | `id` приложения: латиница в нижнем регистре, тот же, что в `apps.json` (`mds`, `react2players`). Приложение, которого на странице ещё нет, всё равно шлёт свой будущий `id`. | Не показывает это приложение в списке. Google Analytics читает метку как источник перехода. |
| `lang` | `ru` или `en` | Выбирает язык страницы и список приложений. |
| `store` | `gp` или `rustore`; если стор неизвестен, параметра нет | Показывает кнопку только этого стора. |

Открывать только во внешнем браузере (`Intent.ACTION_VIEW`), не в WebView: ссылки на
сторы из браузера открываются сами, из WebView — нет.

### Язык

Русскоязычный — тот, у кого русский есть где угодно в списке языков системы, либо
первый язык украинский, белорусский или казахский. Ему `lang=ru`, остальным `lang=en`.

```java
static String pageLang() {
    // Системный список, а не язык приложения: настройка языка внутри приложения
    // не говорит, читает ли человек по-русски.
    LocaleList locales = Resources.getSystem().getConfiguration().getLocales();
    for (int i = 0; i < locales.size(); i++) {
        String code = locales.get(i).getLanguage();
        if (code.equals("ru")) return "ru";
        if (i == 0 && (code.equals("uk") || code.equals("be") || code.equals("kk"))) return "ru";
    }
    return "en";
}
```

`LocaleList` есть с API 24; ниже — `Locale.getDefault()` и то же правило для одного
языка. Приложение, чья аудитория русскоязычна по определению, шлёт `ru` всегда:
так делает МДС.

### Стор

По пакету установщика (`PackageManager.getInstallSourceInfo()` с API 30, раньше —
`getInstallerPackageName()`):

| Установщик | `store` |
|---|---|
| `com.android.vending` | `gp` |
| `ru.vk.store` | `rustore` |
| любой другой или неизвестен | параметр не передавать |

Без параметра страница покажет русскоязычным оба стора, остальным — Google Play.
Пришедшему из Google Play нельзя показывать другие сторы, поэтому для сборок из
Google Play параметр обязателен.

### Когда пункт не показывать

Если для языка пользователя на странице нет ни одного приложения, кроме самого
источника, страница будет пустой. В `apps.json` это видно так: приложений с блоком
`content.<язык>`, не считая своего, ноль. Таким пользователям пункт не показывать.

Сейчас это нерусскоязычные пользователи «Реакции 2 Игрока»: в английском списке
она одна. Русскоязычным есть что показать в любом приложении.

### Пункт меню

- Название: «Наши приложения», по-английски — «Our apps». Совпадает с заголовком
  страницы.
- Отметка «новое». Общее для всех — только условие: в списке есть новое, пока
  версия списка больше той, что пользователь видел; по нажатию приложение
  запоминает текущую версию.
- Как показать новое, каждое приложение решает само, под свой интерфейс. В МДС
  это точка на значке пункта и такая же на кнопке, открывающей меню: отметку
  внутри закрытого меню иначе не увидят.

### Remote Config

| Ключ | Тип | Значение по умолчанию в коде | Зачем |
|---|---|---|---|
| `apps_page_url` | String | `https://android.darklogic.ru/` | Адрес без параметров. Пустая строка прячет пункт. |
| `apps_page_version` | Number | версия списка на момент релиза | Номер версии списка; когда он растёт, появляется отметка «новое». |

Значения по умолчанию обязаны быть в коде: пункт должен работать и без ответа
Remote Config. Параметры ссылки приложение дописывает к адресу само.

Версия списка — поле `version` в `apps.json`. У каждого приложения свой проект
Firebase, поэтому при появлении нового приложения на странице номер поднимается
в Remote Config каждого проекта отдельно.

### Аналитика со стороны приложения

Во всех приложениях одно и то же событие, чтобы отчёты можно было сравнивать.

Событие `apps_page_open`, отправляется перед открытием браузера:

| Параметр | Тип | Значение |
|---|---|---|
| `open_from` | строка | откуда в приложении открыли: `drawer`, `settings`, `about`, `banner` |
| `list_version` | число | версия списка, которая сейчас в Remote Config |
| `had_dot` | 0/1 | была ли в момент нажатия показана отметка «новое», как бы она ни выглядела |

Правила:

- Имена событий и параметров — латиница в нижнем регистре, цифры и `_`. Имя
  с пробелом Firebase отбрасывает молча.
- Не называть параметр `source`: в Google Analytics так называется источник
  трафика, и свой параметр путается с ним в отчётах.
- Параметры один раз регистрируются в проекте Firebase приложения как
  пользовательские измерения с областью «Событие»: `open_from`, `list_version`,
  `had_dot`. Без этого в отчётах консоли их нет.

Что из этого получается:

- **Открытия** — `apps_page_open` в проекте приложения-источника.
- **Дошли до страницы** — `page_view` в проекте страницы с `from_app`, равным `id`
  источника. Разница с открытиями — те, у кого страница не загрузилась.
- **Нажали на стор** — `store_click` в проекте страницы.
- **Установили** — ссылка на Google Play несёт `referrer` с `utm_source=<id
  источника>` и `utm_medium=apps_page`. Firebase в установленном приложении читает
  его сам и показывает как источник первого запуска. Вживую это не проверено.
  У RuStore такого механизма нет.

### Проверка

1. Открыть ссылку со своими параметрами в браузере: своего приложения в списке
   нет, язык и кнопка стора правильные.
2. `adb shell setprop debug.firebase.analytics.app <пакет>` — в DebugView консоли
   Firebase видно `apps_page_open` с тремя параметрами.
3. Сборка, поставленная через `adb`, стор не знает и `store` не шлёт — так и должно быть.

## Добавить приложение на страницу

1. Объект в `apps.json`:

   | Поле | Что это |
   |---|---|
   | `id` | латиница в нижнем регистре; он же `utm_source` и имя папки в `assets` |
   | `package` | пакет приложения |
   | `priority` | место в списке: 1 — первым, дальше по возрастанию. У МДС всегда 1 |
   | `stores` | ссылки `gp` и `rustore`; чего нет в сторе — не указывать |
   | `content.<язык>` | `name`, `tagline` (одна строка), `description` (два-три предложения), `screenshots` с числом файлов и размером полного скриншота |

   Блок `content` есть только для языков, на которых приложение стоит показывать.
   Нет блока `en` — приложения нет в английском списке.

2. Картинки в `assets/<id>/`:
   - `icon.webp` — 192 px;
   - `<язык>/1.webp`, `2.webp`… — скриншоты высотой 1280 px, до шести штук;
   - `<язык>/1-thumb.webp`… — их копии высотой 360 px.

   Материалы берём из листинга в Google Play. К адресу картинки с
   `play-lh.googleusercontent.com` дописывается размер: `=h1280-rw` для скриншота,
   `=h360-rw` для уменьшенной копии. Иконку `=s192` стоит пережать: `cwebp -q 86`.
   Картинки храним здесь, на серверы сторов не ссылаемся.

3. Поднять `version` в `apps.json` и тот же номер — в `apps_page_version` в Remote
   Config каждого приложения, чтобы у пользователей появилась отметка «новое».

4. Закоммитить, запушить, выложить (см. «Выкладка»).

## Как устроена страница

Статическая страница без сборки и без внешних ресурсов: системный шрифт, картинки
лежат рядом.

- `index.html` — вёрстка, стили и скрипт в одном файле.
- `apps.json` — данные; страница рисуется из них. Позже из этого же файла
  приложения смогут брать список для нативного показа.
- `assets/` — иконки и скриншоты.
- `firebase.json`, `.firebaserc` — настройки хостинга.

Что делает скрипт:

- **Язык.** Берёт `lang` из ссылки. Без него применяет то же правило, что и
  приложения, к языкам браузера.
- **Список.** Приложения с блоком `content` на этом языке, кроме `utm_source`,
  по возрастанию `priority`. Если список пуст — строка «Скоро здесь появятся новые
  приложения».
- **Сторы.** С параметром `store` — только он. Без него русскоязычным Google Play
  и RuStore, остальным Google Play. Кнопки — официальные бейджи сторов из
  `assets/badges/`, в одну строку и одной высоты: Google Play требует, чтобы его
  бейдж был не меньше соседних, и запрещает его перекрашивать и обрезать.
  RuStore у левого края, Google Play у правого, в том числе когда он один.
- **Ссылка на Google Play** несёт `referrer`: `utm_source=<источник>&utm_medium=apps_page`,
  а без источника — `utm_source=apps_page&utm_medium=direct`.
- **Скриншоты.** В карточке лента уменьшенных копий; полный размер грузится только
  по нажатию. Кнопка «Назад» закрывает раскрытый скриншот, а не уводит со страницы.
- **Тема** светлая или тёмная по настройке устройства.
- **Бренд** Darklogic не продвигаем: в шапке нет ни названия, ни логотипа.

Все пути относительные. Локально: `python3 -m http.server 8787` в корне; с `file://`
страница не работает, данные загружаются через `fetch`.

## Выкладка

Исходники — в публичном репозитории `Sicness/android-pages`, ветка `main`. Хостинг —
Firebase Hosting, проект `android-c1827`. После пуша:

```bash
firebase deploy --only hosting
```

Что не уходит на хостинг, задаёт `ignore` в `firebase.json`: скрытые файлы и папки
(в том числе `.git`), `CLAUDE.md`, `README.md`. Правило `**/.*/**` там обязательно:
без него содержимое `.git` выкладывается вместе со страницей.

Домен привязан в консоли Firebase; в DNS reg.ru запись CNAME `android` →
`android-c1827.web.app`. Сертификат выпускает и продлевает Firebase.

Запасные адреса той же страницы: `https://android-c1827.web.app` и GitHub Pages
`https://sicness.github.io/android-pages/` (обновляется при каждом пуше в `main`).

## Аналитика страницы

Google Analytics в проекте Firebase `android-c1827`. Идентификатор потока — `GA_ID`
в `index.html`; пустая строка выключает счётчик.

| Событие | Параметры |
|---|---|
| `page_view` | стандартное |
| `screenshot_open` | `app_id`, `index` |
| `store_click` | `app_id`, `store` |

Со всеми событиями уходят `from_app` (значение `utm_source` или `none`),
`page_lang` и `store_ctx` (значение `store` или `none`). Как измерения в проекте
должны быть зарегистрированы `app_id`, `store`, `from_app`, `page_lang`, `store_ctx`.

## Почему так

- **Firebase Hosting, а не GitHub Pages.** GitHub не выпустил сертификат HTTPS для
  домена: его проверка DNS не дожидалась ответа серверов имён reg.ru, хотя
  остальные резолверы и Let's Encrypt домен видели. С сентября 2026 то же самое
  у других доменов на серверах reg.ru. Цена решения: страница зависит от того же
  поставщика, что и аналитика.
- **Не Cloudflare**: в России он замедлен.
- **Свой домен** позволяет сменить хостинг одной DNS-записью. У записи срок жизни
  сутки, и кэш резолверов отдельный для каждого типа запроса: при переезде
  старую запись какое-то время видят по A, AAAA и CNAME независимо.
- **Язык передаёт приложение**, потому что знает о пользователе больше браузера.
- **Репозиторий публичный** — остался таким со времён GitHub Pages.
